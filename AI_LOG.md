# AI_LOG

AI использовал активно: генерил первичный каркас по слоям, дальше правил руками и гонял решения через обсуждение.
## 1. Как использовал

- Генерация первичного кода по ТЗ: реактивное свойство, базы стейт-машины, сервисы, базовый UI, DI-регистрация.
- Как «обсуждалку» вариантов — прогонял альтернативы и выбирал сам: сервис управления vs стейты сами двигают переходы, Singleton vs Transient, загрузка в стейте vs в сервисе.

Примеры промптов (по смыслу):
- «напиши реактивное свойство строго под сигнатуру из ТЗ `IDisposable Subscribe(Action<T>, bool invokeImmediately = true)`: значение через свойство, отписка только через `Dispose`, без голых `event`»;
- «сделай базу стейт-машины — `IState`, `IStatesController<TEnum>`, `StatesController<TEnum>` с `EnterStateAsync(code, ct)` по контракту: сначала `ExitAsync` текущего, потом `EnterAsync` нового.»;
- «вынеси имитацию загрузки из `LoadState` в отдельный сервис `IBootLoader` с `Progress` и `LoadAsync(ct)`.»;
- «собери `RootLifetimeScope`: регистрация настроек-SO, вьюх, стейтов, фабрики и контроллера, запуск через точку входа».

## 2. Где AI ошибался

- Предложил внешний сервис управления, который держит топологию переходов — расходится с ТЗ («стейт переходит сам»). Завернул.
- Зарегистрировал стейты синглтонами, хотя вся идея с фабрикой — про эфемерные стейты. Поймал противоречие, переключил на `Transient`.
- Затащил `IReadOnlyReactiveValue` из варианта B в вариант A — не туда.
- Сначала клал скрипты не в ту папку и оставлял комментарии в коде — против моих требований.
- Формулировки в доках местами были мутные и с англицизмами — переписывал под себя.

## 3. Что переписал / довёл руками

- `RootLifetimeScope` (регистрацию) — доводил сам.
- Архитектурные правки: `Transient` + фабрика, вынос загрузки в `IBootLoader`, тайминги в `BootSettings`, `IObjectResolver` внутри фабрики.
